## Мета

Закріпити протокол ітерації Python та побудувати lazy pipeline, який читає, очищує, розбирає, перевіряє, фільтрує й агрегує CSV-записи автомобілів без повного завантаження файлу до пам'яті.

## Постановка задачі й вхідні дані

Варіант 5 використовує CSV-схему:

```text
id,brand,model,year,price,mileage
```

Потрібно потоково перевіряти записи, фільтрувати за маркою і роком, знаходити найдорожче авто та авто з найменшим пробігом, обчислювати середню ціну, повертати перші N відповідних записів, групувати за маркою після сортування та обробляти пакети. Некоректні записи відхиляються й обліковуються окремо за причинами.

Малий приклад даних із валідними та навмисно некоректними рядками: [`data/cars.csv`](../data/cars.csv). Benchmark генерує окремий тимчасовий набір щонайменше зі 100 000 валідних авто та 10 некоректними контрольними записами.

## Структура та потік обробки

```text
data/cars.csv
    → read_lines
    → clean_lines
    → parse_csv_rows
    → validate_car_rows
    → filter_cars
    → summarize_cars / format_car_rows
    → batched / calculate_statistics
    → результат
```

Основні модулі: `readers.py` читає файл построково; `parsers.py` створює рядки `DictReader`; `validation.py` перетворює та перевіряє поля; `filters.py` виконує lazy-фільтрацію й ранній пошук; `transformations.py` формує короткі записи та рядки експорту; `batches.py` ділить потік на пакети; `analytics.py` обчислює статистику та використовує `itertools`; `pipeline.py` з'єднує етапи.

### Iterable, iterator та generator

Iterable — об'єкт, від якого `iter()` створює iterator. Iterator зберігає позицію обходу, реалізує `__next__()` і після останнього елемента піднімає `StopIteration`. `CarIdIterator` у `iterators.py` — власний одноразовий iterator; `iter(iterator) is iterator`.

Функція з `yield` створює generator object, а її тіло виконується під час `next()`/споживання. Generator зберігає локальний стан між видачами. `read_lines()` використовує `yield from` для передачі рядків файла; `iter_car_records()` делегує валідовані записи. `flatten_nested()` демонструє рекурсивний `yield from`.

### Generator expression, lazy pipeline та `itertools`

`summarize_cars()` повертає generator expression, що створює `CarSummary` лише під час запиту. Pipeline використовує `itertools.chain` для кількох CSV, `islice` для пакетів і перших N збігів, `accumulate` для накопичення вартості, `pairwise` для сусідніх цін та `groupby` для послідовних марок після сортування. `first_car_ids()` обмежує нескінченний потік `count()` через `islice`.

Lazy processing зберігає перевагу малої пам'яті, доки проміжний потік не перетворено на список. Групування вимагає попереднього сортування, тому `group_cars_by_brand()` навмисно матеріалізує записи й використовує O(n) пам'яті; це окремий аналітичний етап, а не базовий streaming pipeline.

### Валідація, фільтрація та агрегація

Обов'язкові поля CSV перетворюються до `int`/`float`. Перевіряються додатний ID, непорожні марка/модель, рік не раніше 1886, скінченна невід'ємна ціна та невід'ємний пробіг. `ValidationStats` накопичує valid/invalid лічильники та категорії помилок зі стабільними назвами.

`filter_cars()` підтримує марку (без урахування регістру) й точний рік. `first_matching_cars()` обмежує результат `islice`, а `find_car_by_id()` припиняє читання після збігу. `calculate_statistics()` одним проходом повертає кількість, середню ціну, найдорожче авто, мінімальний пробіг та частоти марок.

### Пакетна обробка

`batched(iterable, size)` послідовно бере блоки через `islice`; останній пакет може бути коротшим. `flatten_batches()` використовує `yield from`, не створюючи єдиного об'єднаного списку.

## Eager проти lazy: експеримент

Команда `python -m car_catalog.streaming.benchmark` генерує файл на 100 000 валідних авто та 10 некоректних рядків. Eager-реалізація читає весь текст і матеріалізує всі валідні записи; lazy-реалізація зчитує та агрегує послідовно. Перед вимірюванням часу до першого запису та peak memory результати обох режимів звіряються.

Приклад результату одного запуску на Windows / Python 3.14.3:

| Режим | Час повної обробки, с | Peak memory, MiB | Час до першого запису, с | Валідні | Некоректні |
|---|---:|---:|---:|---:|---:|
| eager | 1.9477 | 53.552 | 0.020927 | 100 000 | 10 |
| lazy | 1.3652 | 0.175 | 0.000545 | 100 000 | 10 |

`tracemalloc` вимірює Python allocations, а не всю пам'ять процесу; час залежить від ОС, дискового кешу та навантаження. У цьому запуску lazy-прохід використав приблизно у 306 разів менше пікової Python-пам'яті та приблизно у 38 разів швидше повернув перший запис. Він також швидше завершив повну обробку, однак це не універсальна гарантія: для малих даних eager-варіант інколи простіший, а повторний обхід lazy-джерела потребує його повторного створення. `groupby` із сортуванням залишається окремим O(n)-memory винятком.

## Аналіз складності

| Операція | Час | Додаткова пам'ять |
|---|---:|---:|
| Читання, очищення, parsing і validation | O(n) | O(1) на запис |
| Фільтрація чи ранній пошук за ID | O(n), за раннього збігу може бути менше | O(1) |
| Streaming average / min / max / підрахунок марок | O(n) | O(u) для u різних марок |
| Пакет розміру b | O(n) загалом | O(b) |
| Перші N збігів | до O(n) | O(N) для спожитого результату |
| Сортування перед `groupby` | O(n log n) | O(n) |
| Eager читання/агрегація | O(n) | O(n) |

## Відповіді на контрольні запитання

1. **Iterable** — об'єкт, з якого можна отримати iterator через `iter()`.
2. **Iterator** — об'єкт, який пам'ятає стан обходу та видає наступне значення.
3. Iterable створює iterator; iterator сам видає значення і зазвичай витрачається одноразово.
4. `iter()` отримує iterator від iterable або перевіряє iterator protocol.
5. `next()` запитує наступне значення iterator.
6. `__iter__()` повертає iterator; для iterator зазвичай повертає `self`.
7. `__next__()` повертає наступне значення або піднімає `StopIteration`.
8. `StopIteration` сигналізує, що iterator вичерпано.
9. `for` викликає `iter()`, потім `next()` до `StopIteration`.
10. Iterator одноразовий, бо зберігає поточну позицію й після кінця не відновлюється автоматично.
11. `iter(iterator) is iterator`, бо iterator уже реалізує протокол і зберігає стан.
12. Ні; для нового проходу треба створити новий generator.
13. Generator function — функція з `yield`, що повертає generator object.
14. `yield` видає значення й призупиняє функцію зі збереженням стану.
15. `return` завершує функцію; `yield` призупиняє generator для наступного запиту.
16. Тіло generator function починає виконуватися при першому споживанні, наприклад `next()`.
17. Generator зберігає локальні змінні, позицію виконання та стан циклів.
18. Generator expression — компактний lazy вираз `(x for x in values)`.
19. List comprehension одразу створює список; generator expression обчислює значення на запит.
20. Lazy evaluation обчислює елемент лише коли його запитує споживач.
21. Eager evaluation обчислює та часто матеріалізує всі результати одразу.
22. Lazy зменшує проміжні дані в пам'яті, дає ранній результат і підтримує early termination.
23. Lazy важче повторно обходити, помилки виникають під час споживання, а дані можуть вимагати відкритого ресурсу.
24. Streaming — послідовна обробка даних частинами без повного завантаження.
25. Він обмежує споживання RAM, навіть коли файл великий.
26. `read()` завантажує весь файл у пам'ять і може вичерпати RAM.
27. File object реалізує iterable protocol і видає рядки послідовно.
28. `yield from` делегує видачу значень іншому iterable/generator.
29. `itertools` — стандартний модуль ефективних ітераторних building blocks.
30. `count()` створює нескінченну арифметичну послідовність.
31. Без обмеження споживання нескінченного iterator не завершиться.
32. `islice()` бере задану ділянку iterator без його повної матеріалізації.
33. `chain()` послідовно об'єднує кілька iterable.
34. `takewhile()` видає елементи, доки предикат істинний; перший невідповідний елемент споживається.
35. `dropwhile()` пропускає елементи, доки предикат істинний, потім видає решту.
36. `accumulate()` видає проміжні результати накопичення (за замовчуванням — суму).
37. `pairwise()` видає пари сусідніх елементів.
38. `groupby()` формує групи сусідніх однакових ключів.
39. Сортування ставить однакові ключі поруч; без цього одна група може з'явитися кілька разів.
40. `product()` генерує декартів добуток iterable.
41. `combinations()` не враховує порядок вибраних елементів; `permutations()` враховує.
42. Навіть lazy combinatorial iterator може мати астрономічну кількість результатів і зайняти надто багато часу.
43. Batching ділить потік на блоки обмеженого розміру.
44. Пакети керують піковою пам'яттю й дають ефективно групувати I/O чи обчислення.
45. Lazy pipeline — ланцюг генераторних етапів, які передають записи без створення повних проміжних списків.
46. Типові етапи: source, parsing, validation, filtering, transformation, aggregation і sink.
47. Source — джерело даних, наприклад CSV-файл або generator.
48. Transformation — етап, що перетворює запис у новий формат.
49. Sink — кінцевий споживач: агрегатор, файл, база даних або вивід.
50. Ні; генератор заощаджує пам'ять, але не гарантує меншого часу.
51. Одночасно зберігається поточний елемент/стан, а не повний набір результатів.
52. Time to first result — час від початку операції до першого доступного результату.
53. Споживач може припинити ітерацію одразу після потрібного елемента, як у `find_car_by_id`.
54. Generator виконує тіло під час ітерації, тому виняток може виникнути лише при запиті відповідного елемента.
55. `list(generator)` матеріалізує всі значення та може нівелювати перевагу пам'яті.
56. `list(count())` не завершиться й поступово вичерпає пам'ять.
57. Відкритий файл живе, поки generator його читає; його треба вичерпати або закрити, щоб завершити роботу з ресурсом.
58. Перевіряти кілька очікуваних елементів, `list()` для малих генераторів і крайні випадки порожнього вводу.
59. Використати `islice()` або обмежене число `next()` викликів.
60. Список доречний для малого повторно обхідного набору; generator — для великого, потокового або достроково перериваного вводу.

## Висновок

Реалізовано перевірений потоковий pipeline для каталогу автомобілів: CSV проходить через читання, очищення, parsing, validation, фільтрацію, трансформацію та агрегацію. `yield`, `yield from`, generator expression і засоби `itertools` забезпечують обробку без повної eager-матеріалізації. Експеримент на 100 000 записів підтвердив значно нижчий peak memory lazy-варіанта на виміряній системі; сортування для `groupby` потребує окремої матеріалізації й враховане в оцінці складності.
